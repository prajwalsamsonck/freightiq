# Contributing

## Development setup

Follow the installation steps in the README, activate the project environment, and run the full verification commands before opening a change.

## Pull requests

- Keep changes focused and explain the user or engineering outcome.
- Add or update tests for behavior changes.
- Do not commit `.env` files, credentials, generated databases, build output, or personal working files.
- Keep synthetic data clearly labelled and preserve the prototype disclaimer.
- Include screenshots when changing the browser or Streamlit presentation.

## Commit style

Use short, imperative commit messages such as `Add route-aware forecast comparison` or `Fix scenario reset state`.
